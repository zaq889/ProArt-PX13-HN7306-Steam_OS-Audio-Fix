## 1. Device & Environment
- Model: ASUS ProArt PX13 (HN7306), stock SteamOS.
- SSH: `deck@192.168.10.121`, password `user123` (sudo uses the same password).
  ⚠️ Sensitive — for local maintenance only, do not share; changing the password is advised.
- Kernel: `7.2.7-valve2-2-neptune-72`; PipeWire `1.6.8`; WirePlumber `0.5.18`.
- SteamOS mechanics: `steamos-readonly` is enabled by default; `/usr` is overwritten on
  system updates. `/etc` and `/home/deck` are a persistent overlay that survives updates.
- Workflow: use PowerShell `exec_command` on the Windows side and the SSH session
  (`write_stdin`) on the target. ⚠️ Every command sent must end with a newline, or the
  shell will not execute it.

## 2. Problems & Root Causes (conclusions)
1. **No speaker sound**: the `amdsoundwire` card has an empty `CardComponents`, so the
   ALSA UCM cannot derive the codecs and PipeWire falls back to `Dummy Output`.
2. **No hardware speaker/headphone sink (missing TAS2783 firmware)**: the two TAS2783
   amps need per-laptop calibration blobs. Without them the kernel logs
   `Direct firmware load for 1714-1-0x8.bin failed` and
   `error playback without fw download`; the speaker PCM probe returns `-EINVAL`, so
   PipeWire drops the whole `HiFi` UCM profile. The card then exposes only `off`, and
   both the Speaker and Headphones sinks disappear (not just the speakers).
   - Fixed by installing `1714-1-0x8.bin` / `1714-1-0xB.bin` (plus fallback names
     `1714-1-8.bin` / `1714-1-B.bin`) from `firmware/`.
3. **No right-channel audio (identified; kernel bug)**: the two TAS2783 amps sit in
   SoundWire mirror mode and both take the same block offset (slot 0), rendering only
   the left channel.
   - Upstream reference: Ville Saarinen, `ASoC: tas2783: add RX Single Channel Switch
     to split a two-amp stereo pair` (2026-08). This box has no kernel headers, so a
     local build is not possible; the only real fix is Valve merging the patch or
     switching to a third-party kernel (switching kernels risks the A/B update
     mechanism and is not recommended).
4. **3.5mm headphone jack not detected (kernel bug)**: on kernel
   `7.2.7-valve2-2-neptune-72`, `Headphone Jack` / `Headset Mic Jack` stay `off`
   even with a known-good headphone fully inserted; `evtest /dev/input/event22`
   shows `SW_HEADPHONE_INSERT state 0`. The rt721 PCM receives audio but the
   codec's analog output stays off.
   - This is the RT721-SDCA type-detection / vendor analog power-gate issue fixed
     by the RT721 patches that landed around Linux 7.3-rc7 (LKML, 2026-10). The
     current SteamOS 7.2.7 kernel predates them. There is no userspace/UCM fix;
     the jack auto-switch Lua hook cannot fire until the kernel reports the plug.
   - Workaround until Valve ships a newer kernel: Bluetooth or USB-C headphones.
     Do not install a custom kernel/DKMS without explicit user consent.
5. **Wi-Fi log spam**: iwd logs `ath12k scan start failure` every 15 s.
6. **`SDW1-PIN4-CAPTURE-SmartAmp: ASoC error (-22)`**: the machine driver registers a
   capture DAI for the TAS2783, which is playback-only, so `prepare/hw_params` returns
   -22. It bursts once (about 20 lines) whenever wireplumber/pipewire starts. It does
   not affect playback or the microphone. A real fix requires a kernel patch to remove
   that capture DAI; there is no userspace toggle.
7. Bluetooth is Quectel (`2c7c:0130`), not MT7925, so the AUR `btusb` patch does not
   apply (not used).
8. No amdgpu/thermal anomalies found in the journal (checked).

## 3. Fixes Already Applied (current target state)
1. **UCM override**: `/usr/share/alsa/ucm2/conf.d/amd-soundwire/ASUSTeKCOMPUTERINC.-ProArtPX13HN7306EA-1.0-HN7306EA.conf`
   (a copy of the stock `sof-soundwire.conf` with forced `SpeakerCodec1=tas2783`,
   `Headset/Mic=rt721`).
2. **Speaker profile**: `/usr/share/alsa/ucm2/sof-soundwire/tas2783.conf`
   (`PlaybackPCM hw:${CardId},2`, 2ch, EnableSequence switches on Left/Right Spk and
   sets volume).
3. **TAS2783 calibration firmware**: `/lib/firmware/1714-1-0x8.bin`,
   `1714-1-8.bin`, `1714-1-0xB.bin`, `1714-1-B.bin` (also copied to
   `/lib/firmware/ti/audio/tas2783/`). Without these the amps reject playback and
   PipeWire collapses the card to the `off` profile (see §2 item 2).
4. **ACP PCI rebind**: `/usr/local/sbin/px13-audio-fix.sh` plus two enabled systemd
   services `px13-audio-rebind.service` (boot) and `px13-audio-resume.service` (resume).
5. **Wi-Fi spam**: `/etc/iwd/main.conf` with `[Scan] DisablePeriodicScan=true`.
6. **Right-channel workaround (mono downmix)**: `~/.config/pipewire/pipewire.conf.d/50-px13-mono.conf`
   creates a `px13_speaker_mono` mono virtual sink via loopback; the default sink is
   pinned in the WirePlumber state file `~/.local/state/wireplumber/default-nodes`.
   - Volume note: the mono sink feeds the real `HiFi__Speaker__sink`, so volume is
     applied twice. Keep the real Speaker sink at **100%** and use only the
     `ProArt PX13 Speakers (mono)` slider; otherwise 40% × 40% ≈ 16% sounds almost
     silent.
7. **Headphone jack auto-switch**: `~/.config/wireplumber/scripts/px13-jack-switch.lua`
   (a default-node selection hook: headphone plug → Headphones sink, unplug → mono
   speaker sink), loaded as a component via `~/.config/wireplumber/wireplumber.conf.d/60-px13-jack-switch.conf`
   (absolute-path script name; WP 0.5 does not support `main.lua.d`).
   - Verified: the mono branch works (log `no headphones - selecting mono speaker sink`).
     The plug branch is installed but **cannot fire on the current 7.2.7 kernel**
     because the RT721 driver never reports the jack (see §2 item 4); it will start
     working automatically once a kernel with the RT721 fixes is installed.

## 5. After Reinstall / New Machine
- GUI: copy this folder from USB to the SteamOS desktop → right-click
  `install-px13-fix.desktop` → "Allow Launching" → double-click → enter password →
  reboot.
  - The launcher strips an optional `file://` prefix from `%k` and invokes `bash`, so it
    also works after copying from a FAT/exFAT USB drive where executable bits are lost.
    Only the `.desktop` file itself needs "Allow Launching" (executable bit).
- Terminal:
  ```
  sudo steamos-readonly disable
  sudo bash px13-audio-install.sh
  ```
- Note: the installer runs as root and writes the mono/jack config under `/home/deck`
  with a `chown`.
- Keep the whole folder together: the installer looks for `firmware/` next to itself
  (`SELF_DIR`). Copying only the script will install everything except the speaker
  calibration blobs, and the card will fall back to the `off` profile again.
- After installing the firmware, run `sudo systemctl restart px13-audio-rebind.service`
  (or reboot) so the amps re-probe and load it; no other unplugging is needed.

## 6. Verification
- `pactl list cards` → the `amd_sdw` card must show `Active Profile: HiFi`.
  If it shows `off`, check `journalctl -k -b | grep -i tas2783` for
  `Direct firmware load ... failed` or `error playback without fw download`
  (missing/renamed firmware).
- `pactl get-default-sink` should print `px13_speaker_mono`.
- `pactl list short sinks` should include
  `...HiFi__Speaker__sink` and `...HiFi__Headphones__sink` (the latter `SUSPENDED`
  while the jack is empty).
- Volume: keep `...HiFi__Speaker__sink` at 100% and adjust only
  `px13_speaker_mono`; two low sliders multiply and make the speakers nearly silent.
- Stereo→mono test (after downmix both speakers should sound):
  ```
  speaker-test -c 2 -t wav -l 1
  ```
- Direct amp check (right channel still only carries left content; known kernel bug):
  ```
  speaker-test -D hw:1,2 -c 2 -s 1 -t wav -l 1
  ```
- Headphones (current 7.2.7 kernel): plugging in will **not** switch and will not
  play. Confirm the kernel bug with:
  ```
  amixer -c 1 cget numid=15          # Headphone Jack: values=off even when plugged
  sudo evtest /dev/input/event22     # SW_HEADPHONE_INSERT state 0
  ```
  The `px13-jack-switch.lua` hook is installed but cannot fire until the RT721
  driver reports the plug (see §2 item 4). Use Bluetooth/USB-C headphones for now.
  On a kernel with the RT721 fixes, `pactl get-default-sink` should switch to
  `...HiFi__Headphones__sink` and back to `px13_speaker_mono` on unplug.
- Optional firmware sanity check:
  ```
  sha256sum /lib/firmware/1714-1-0x8.bin /lib/firmware/1714-1-0xB.bin
  ```
  Expected: `9a105de5...` and `a975dc7e...` (full hashes in `firmware/README.txt`).

## 8. Do NOT Do (important)
- Do not run `pacman -Syu`, do not switch kernels (including `linux-cachyos-px13`),
  and do not touch the A/B update mechanism unless the user explicitly agrees.
- Do not reboot the target unless the user explicitly agrees.
- Do not edit UCM files under `/usr` without running `steamos-readonly disable` first.
- Do not delete `firmware/` from this pack or `/lib/firmware/1714-1-*.bin` from the
  target; without them the sound card loses its `HiFi` profile entirely.
- Do not replace the firmware blobs with files fetched from `git.kernel.org` — that
  host returns an HTML bot-check page (7758 bytes), which the kernel cannot load.
- Do not install a custom kernel, DKMS module, or patched `snd-soc-rt721-sdca` just to
  get the 3.5mm jack working without explicit user consent; it can break SteamOS
  updates. Wait for Valve's kernel update instead.

## 9. Sessions & Recovery
- SSH is not enabled at boot; start it on the target with `sudo systemctl start sshd`.
  Log in as `deck` / `user123` (password auth). The target is currently wired at
  `192.168.10.121` on `enp198s0f0u2`, so restarting `iwd` does not drop the session.
- The old temporary OpenSSH key (`...\Temp\px13key\k2`) is **no longer authorized**.
  From Windows use Posh-SSH with the password (as in this session), or add a new key.
- The desktop folder name contains Chinese characters and renders garbled over SSH;
  locate it with `find /home/deck -maxdepth 2 -type d -name ProArt-PX13-Audio-Fix`
  instead of typing the path.
- Upload new pack files to `/tmp/...` via SFTP, run `bash -n` first, then
  `sudo bash /tmp/.../px13-audio-install.sh`. Last idempotency run: 2026-10-31 02:32,
  result `installed: 1`, card still `Active Profile: HiFi`.
- If an interactive SSH session appears stuck, the command most likely lacked a
  trailing newline — send one more newline, or press `Ctrl+C` (`\x03`).
- Re-pull files with Posh-SSH `Get-SFTPItem` (password auth), not the revoked key.
